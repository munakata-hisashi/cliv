# 収集失敗の通知と検証

## 目的

「未導入」「導入済みだが空一覧」「収集失敗」を誤解させず、取得できた結果は利用可能にする。特に JSON 利用者が不完全な結果を完全な一覧として扱わないことを重視する。

## 終了コードと出力

| 状態 | 終了コード | stdout | stderr |
|---|---:|---|---|
| 正常収集 | 0 | 表または JSON 配列 | なし |
| 管理ツール未導入 | 0 | そのソースを省略 | なし |
| 空一覧／設定で無効 | 0 | そのソースを省略 | なし |
| 一部の収集失敗 | 1 | 取得できた部分結果 | ソース別のエラーと不完全な一覧という警告 |
| すべて収集失敗 | 1 | 空の表／JSON の `[]` | ソース別のエラーと不完全な一覧という警告 |
| 出力失敗 | 1 | 出力途中の場合がある | 出力エラー |
| 不正な引数 | 2 | 通常なし | 引数エラー |

未導入と正常な空一覧はどちらも失敗ではない。通常表示では区別せず静かに省略するが、収集失敗は空一覧と区別する。

失敗例：

```text
cliv: brew: exit status 1: <外部コマンドのエラー>
cliv: incomplete inventory: collection failed for brew
```

JSON の形式は配列のまま維持し、エラーは混ぜない。全ソース失敗時も有効な `[]` を出力するが、終了コードは1なので完全な空一覧とは区別できる。collector が部分結果とエラーを同時に返した場合は部分結果を残す。

## ソース固有の失敗

- 外部コマンドの失敗は stderr の内容があればエラー説明に含める。
- npm は出力が有効な JSON でも非ゼロ終了を無視しない。JSON の `error` または非空の `problems` も収集失敗とする。読み取れたパッケージは残す。
- manual は設定された `version_command` の非ゼロ終了、タイムアウト、空出力、バージョンを認識できない出力を失敗とする。該当ツールを `unknown` で残し、他の登録も処理する。
- manual の `version_command` 未設定は従来どおり `unknown`。取得を試していないため失敗とはしない。
- `--source` で選ばれていない collector は起動せず、その失敗も報告しない。

以前は collector が失敗しても cliv が正常終了する場合があった。終了コード1への変更は JSON を使うスクリプトにも影響するため、利用側は終了コードを確認する。

## スクリプトでの利用

```sh
if cliv --json > tools.json; then
  # 完全な収集結果として使用する
  jq '.' tools.json
else
  # ファイルには部分結果が入ることがある。完全な一覧として使用しない
  echo 'ツール一覧の取得に失敗しました' >&2
fi
```

`cliv --json | jq ...` のパイプでは、シェルが末尾のコマンドの終了コードのみを返すことがある。Bash などでは `set -o pipefail` を使うか、上のように cliv を単独で実行して終了コードを確認する。

## 検証指標

障害時の明確さは、固定シナリオで以下の判定がすべて成立することを目標とする。

1. **失敗検出**：収集失敗時に終了コード1となる。
2. **原因の識別**：失敗したソースと不完全な一覧の警告が stderr にある。
3. **部分結果の保持**：正常なソースや同じ collector 内の取得済み結果を失わない。
4. **誤警告の抑制**：未導入・空一覧・未選択ソースを失敗扱いしない。
5. **JSON の利用可能性**：部分失敗でも stdout は有効な JSON 配列。

```sh
go test ./cmd/cliv ./internal/collector -v
```

- `cmd/cliv/failure_test.go`：部分失敗、全失敗、空一覧、ソース選択、部分行の保持、出力失敗。
- `cmd/cliv/integration_test.go`：実バイナリと偽の uv を使い、未導入・空一覧・非ゼロ終了・不正出力の終了コードを検証。POSIX シェルを使うため Windows ではこのテストのみスキップする。
- `internal/collector/failure_test.go`：manual の失敗と継続、npm のエラーメタデータ。

実環境の管理ツールや設定を壊さず、独立した一時ディレクトリと偽のコマンドで検証する。これらのテストは通常の `go test ./...` と CI に含まれる。収集率・実行時間のスクリプトも、非ゼロ終了や stderr を計測失敗として扱う。
